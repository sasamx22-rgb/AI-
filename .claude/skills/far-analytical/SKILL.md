# FAR(정산표 + 분석적 절차) 작성 스킬

## 준비물 (저장소 안, 커밋 제외)

- 표준 양식(마스터, 수정 금지 — 항상 복사해서 쓴다)
  - `templates/FAR_master_v1.xlsx` : K-IFRS용. 계정을 **공시계정**(FAR C열)으로 매핑한다. 시트: 사용안내·공시BS·공시IS·공시CIE·공시CF·왜곡표시·FAR
  - `templates/FAR_master_KGAAP_v1.xlsx` : 일반기업회계기준용. **회사 재무제표 계정과목을 그대로** 쓴다. 시트: 사용안내·공시BS·공시IS·왜곡표시·FAR
- 도구(모두 회사 PC의 Excel로 동작, PowerShell 실행 정책에 막히면 `powershell -ExecutionPolicy Bypass -File …`):
  - `tools/excel-dump.ps1` : 원본 재무제표·산출 엑셀을 읽기 전용으로 텍스트 덤프. 원본 파악은 `-Compact`(시트 전체·숨김 시트 표시·라벨 한 줄 형식, 전 시트 약 8초)를 쓴다. `-List`는 시트 목록만.
  - **`tools/far-run.ps1` : 권장 경로.** 작업 파일(job) 하나로 마스터 복사 → 계정 행 추가 → 원본에서 값 읽어 입력 → 합계 대조 → 검증 보고까지 **Excel 한 번 실행**(약 1분 이내)으로 끝낸다. 계정은 행 번호가 아니라 **이름**으로 지정하므로 행이 밀려도 상관없다. 사용법은 스크립트 머리말.
  - `tools/far-tool.ps1 -Action Fill|AddAccount|Check` : 작업 파일 없이 개별 수정할 때(행 번호 기준). 사용법은 스크립트 머리말.
- 회사 고유 산식이 새로 주어지면 이 스킬의 "분석 산식" 절에 반영한다.

## 0단계 — 작업 전 확인 (한 번에 묻는다)

**먼저 `companies/<약칭>/notes.md`의 "설정" 블록(아래 "회사별 폴더 규칙" 참고)을 읽는다. 거기 이미 있는 값은 다시 묻지 않는다.** 사용자가 말하지 않았고 설정에도 없는 것만 묻는다. 먼저 재무제표를 훑어 추정한 뒤 "이렇게 이해했습니다, 맞나요?" 한 번으로 확인한다.

1. 회계기준: K-IFRS / 일반기업회계기준 (계정 체계·표 제목·자본 항목으로 추정 가능)
2. 별도 / 연결
3. 단위 (원 / 천원 / 백만원) — 마스터는 원 단위 기준이다. 도구가 원본 시트 윗부분의 "(단위: …)" 표시를 읽어 **원 단위로 자동 환산**하고, 원본-FAR 대조에도 같은 환산을 적용한다(직접 환산해서 입력하지 않는다). **원본에 단위 표시가 없으면 원 단위로 보고** 진행하며 `gate.txt`에 경고가 남는다. 단위 표시는 없지만 천원·백만원 단위인 걸 아는 원본에만 작업 파일에 `UNIT|천원`·`UNIT|백만원` 줄을 적는다. 시트마다 단위 표시가 다르거나 `UNIT` 줄이 원본 표시와 다르면 저장되지 않으니 사용자에게 확인한다
4. 당기·전기 기간(개월): 당기 결산일과 기간을 재무제표 헤더에서 읽는다. 읽히지 않으면 사용자에게 묻거나 빈칸으로 두고 알림(Q5)이 뜨는 상태로 넘긴다. 연환산은 워크북이 `12/개월`로 자동 처리한다
5. 조정분개(왜곡표시)가 있는지 — 없으면 Dr/Cr 열은 비워 둔다
6. **분석 블록 입력칸 점검 (작업 시작 시 한 번에)**: 재무제표를 훑은 뒤, 분석 블록이 요구하는 입력(기초매출채권·기초매입채무·기초제품·기초상품·기초원재료 등 전전기말 잔액)이 원본에 없으면 **그 목록을 이때 한꺼번에 묻는다.** 나중에 하나씩 묻지 않는다. 사용자가 없다고 하면 해당 지표의 코멘트에 "기초 미입력으로 전기 평균이 기말 기준임, 비교 불가"를 적는다.
7. **분석 산식과 회사 성격의 불일치 점검**: 양식의 분모·분자가 이 회사의 계정과 맞는지 본다(예: 매입채무 분석은 원재료 매입액 기준인데 회사는 **상품 매입**만 있는 경우). 맞지 않으면 산식을 임의로 바꾸지 말고 사용자에게 "상품 매입 기준으로 산식을 바꿀까요?"를 묻는다. 답이 오기 전에는 해당 지표 코멘트에 "미산출 사유"를 적는다.
8. **원본 정합성 의문**: 재고자산 증감이 매출원가에 반영되지 않았거나, 매출은 있는데 매출원가가 0인 것처럼 **원본 자체가 이상해 보이는 곳**은 고치지 말고 코멘트와 응답에 "원본 확인 필요"로 남긴다.

위 질문은 **결과 숫자·산식에 영향이 있는 것만** 묻는다(결과에 영향 없는 표기·스타일은 가정하고 응답의 "가정" 항목에 적는다). 질문할 때는 번호를 붙여 한 번에 모아 묻고, 그 턴에서는 정산표 작업을 더 진행하지 않고 응답 마지막 줄에 `[확인필요]`를 붙여 끝낸다(executor.md의 "확인필요" 규칙).

## 회사별 폴더 규칙 (먼저 확인)

회사별 자료는 `companies/` 한 곳에 모은다(저장소가 Public이라 `.gitignore`로 커밋 제외). **이 PC에만 있다.**

```text
companies/
  README.md               약칭 ↔ 한글 정식명 대응표 (새 회사를 만들면 한 줄 추가)
  <약칭>/
    dict.txt              계정 사전 (ADD/MAP/SKIP/TIE, # 주석에 근거와 확정 날짜)
    notes.md              회계기준, 별도/연결, 단위, 결산월, 판단 근거
    FY<연도>/
      source/             그 해 원본 재무제표
      reference/          (초기 세팅 때만) 사용자가 만든 기존 정산표 — 계정 대응을 배우는 용도
      job.txt             그 해 작업 파일
      verify/             gate.txt 등 도구 보고서와 제임스 검토 자료
outputs/<약칭>/FAR_<약칭>_FY<연도>-v<N>.xlsx   작업 버전(초안). 최종본은 -final.xlsx (파일명 규칙은 아래 "버전과 최종본")
```

- **산출물 위치: `outputs/<약칭>/`** — 회사별로 하위 폴더를 두고 그 안에 버전·최종본·`_history`를 모은다(폴더가 없으면 도구가 만든다). 채팅 앱의 변경 감지·산출물 트레이는 하위 폴더도 보므로 제임스 자동 검토가 그대로 이어진다.
- **버전과 최종본 (같은 회사·같은 결산일을 여러 번 만들 때)**
  - 파일명: `outputs/<약칭>/FAR_<약칭>_FY<연도>-v<N>.xlsx`(N=1,2,…). 처음은 v1이다.
  - **새 버전을 만드는 경우**: 제임스 검토를 한 번 거친 뒤의 수정, 사용자 지적 반영, 결산 조정 같은 내용 변경. 이전 버전은 그대로 둔다. **덮어쓰는 경우**: 아직 아무도 검토하지 않은 최신 초안을 에이미가 스스로 오류를 잡아 다시 만들 때(같은 버전 번호 유지, 실패하면 기존 파일이 그대로 남는다).
  - `-final`은 **제임스가 승인한 버전**을 복사한 것이다(`FAR_<약칭>_FY<연도>-final.xlsx` + `-final.record.txt`). 제임스 검토를 거치지 않은 파일은 어떤 경우에도 `-final`이 아니다. 사용자가 "최종"이라고 했는데 최신 버전이 아직 승인되지 않았으면 만들지 말고 "제임스 검토 전입니다. 검토를 먼저 할까요?"를 질문 카드로 묻는다.
  - **"<회사명> 정산표 최종" 처리**: 같은 회사·같은 결산일의 `-final`이 승인된 상태에서 사용자가 최종이라고 하면, 지울 목록을 질문 카드로 먼저 보인다(옵션 `정리`/`그대로 두기`). 예: "v1, v2, v3을 `outputs/<약칭>/_history/`로 옮깁니다. 최종본·승인 기록·`verify/`는 유지". `정리`를 받으면 **삭제하지 않고** 이전 버전들을 `outputs/<약칭>/_history/`로 옮기며(같은 회사·같은 결산일만, 다른 회사·연도 파일은 건드리지 않는다), `_history`의 30일 지난 파일 비우기는 사용자가 따로 시킬 때만 한다.
  - 새 최종본을 만들기 직전에 기존 `-final.xlsx`와 `-final.record.txt`를 `outputs/<약칭>/_history/`로 `이름-<YYYYMMDD-HHmm>` 형태로 옮긴 뒤 만든다(기존 최종본은 지우거나 덮어쓰지 않는다).
  - `verify/`에는 가장 최근 실행의 자료가 있다. 승인된 버전을 만든 실행의 자료이므로, 승인 뒤에는 그 버전을 다시 만들지 않는다(고치려면 새 버전).
- 산출물 엑셀을 `outputs/`에 두는 이유: 채팅 앱의 산출물 변경 감지와 제임스 자동 검토 연결이 `outputs/`를 보기 때문이다.
- **약칭**은 영문 소문자·숫자(예: `hanil`). 한글·공백은 쓰지 않는다 — far-run.ps1은 ASCII 전용이라 한글 경로에서 인코딩 문제가 날 수 있다. 한글 정식명은 `README.md`·`notes.md`에 적는다.
- **연도 폴더**는 회계연도(`FY2025` = 결산일이 속한 해). 12월 결산이 아닌 회사가 있으므로 결산일을 `notes.md`와 `job.txt`의 `PERIOD`에 명시한다.
- 사용자가 회사명을 말하면 `companies/README.md`에서 약칭을 찾는다. **비슷한 이름이 여럿이거나 확신이 없으면 추정하지 말고 사용자에게 어느 회사인지 묻는다.**
- **`notes.md`의 "설정" 블록**: 해마다 바뀌지 않는 값을 `키: 값` 한 줄씩 적는다 — `정식명`, `회계기준`, `별도/연결`, `결산월`, `단위`(원본 표시와 다르면 `UNIT`), `기초잔액 제공 방식`(예: 전전기 재무제표를 따로 받음/없음), `특이사항`. **첫 작업**에서는 0단계 질문을 질문 카드 한 장으로 묶어 묻고 답을 이 블록에 저장한다. **다음 기**에는 이 블록을 읽어 "A사 2026 해줘"만으로 시작하고, 값이 바뀌었는지 의심되는 것(원본 단위 표시, 결산일 등)만 묻는다. 회계기준·결산월 같은 값이 원본과 어긋나면 설정을 믿지 말고 사용자에게 확인한다.
- **새 회사**: 약칭을 사용자에게 확인받고 폴더·`README.md` 줄·`notes.md`를 만든다. 첫 작업에서 확정한 대응(`MAP`/`ADD`/`SKIP`/`TIE`)을 `dict.txt`에 근거 주석과 함께 저장한다. 에이미는 대화 사이의 기억이 없으므로 **사전 파일이 곧 학습 결과**다.
- **원본 재무제표**는 채팅 앱 업로드로 `inputs/`에 들어온다. 에이미가 파일 내용(회사명·기간)으로 어느 회사·연도인지 판단해 `companies/<약칭>/FY<연도>/source/`로 **옮긴다**(`inputs/`에 같은 파일을 남기지 않는다). 회사·연도를 판단할 수 없으면 묻는다.
- **기존 회사의 다음 기**: `dict.txt`를 불러와 `unmapped.txt`에 나온 계정(새 계정·이름이 바뀐 계정)만 판단하고, 그 결과를 `dict.txt`에 추가한다. 작업 전에 사전 점검표를 만들어 `추정`·미표시 항목을 먼저 확인한다(아래 "사전 항목의 확정·추정 표시").

### 사전 항목의 확정·추정 표시

한 번 잘못 매핑하면 매년 반복되므로 `dict.txt`의 항목마다 신뢰 수준을 표시한다. 항목 블록 **위의 주석 줄**이 그 아래 항목들(다음 표시 줄 전까지)의 상태를 정한다.

```text
#[확정] 2026-10-06 사용자 확인: 상품 매입 기준으로 산식 적용
MAP|BS|...
#[추정] 계정명이 비슷해 매핑함 — 다음 기 첫 작업 때 다시 확인
MAP|BS|...
```

- 사용자가 답했거나 원본·합계 대사로 확인된 것만 `#[확정] 날짜 근거`로 적는다. 에이미가 성격을 보고 판단한 것은 `#[추정] 이유`로 적는다. 표시가 없으면 미표시로 취급한다.
- 점검표: `powershell -ExecutionPolicy Bypass -File tools\far-dict-report.ps1 -Dict companies\<약칭>\dict.txt -OutFile companies\<약칭>\FY<연도>\verify\dict-review.txt` — `추정`·미표시 항목을 먼저, `확정`을 마지막에 보여 준다(추정·미표시가 있으면 종료 코드 1이지만 작업을 막지는 않는다).
- **첫 해 끝**: 사용자에게 `추정` 항목 목록을 질문 카드(옵션 `맞음`/`수정 필요`)로 확인받고 답이 온 것은 `확정`으로 바꾼다. **다음 기 시작**: `확정`은 그대로 쓰고, `추정`·미표시는 결과 숫자가 이상하면(전기 대비 점검에서 걸리면) 가장 먼저 의심한다.

## 회사 초기 세팅 — 사용자가 만든 기존 정산표에서 계정 대응 배우기

사용자가 한 회사의 **이미 완성한 정산표**(양식은 회사마다 다르다)와 그 근거 재무제표를 주면서 "초기 세팅", "이 회사 규칙 저장해줘", "기존 정산표 학습해줘"라고 하는 경우의 절차다. 목표는 **계정 대응(사전)만 저장**하는 것이고, 산출물은 항상 마스터 양식으로 만든다. 코멘트 문체·서식은 배우지 않는다(해마다 내용이 달라 재사용이 적고 토큰만 든다). 이 작업은 산출물을 만드는 일이 아니므로 **제임스 검토를 하지 않고, 결과 파일을 `outputs/`에 두지 않는다**(채팅 앱의 자동 검토가 켜지지 않게 한다).

1. **준비**: 약칭 확인, 폴더·`companies/README.md` 줄·`notes.md` 설정 블록을 만든다(0단계 질문은 질문 카드 한 장으로 묶는다). 사용자의 기존 정산표는 `companies/<약칭>/FY<연도>/reference/`로 옮기고, 근거 재무제표는 `source/`로 옮긴다(`inputs/`에 남기지 않는다). 같은 결산기(연도)의 정산표와 재무제표인지 확인한다. **정산표와 재무제표가 한 파일의 서로 다른 시트에 같이 들어 있어도 된다** — 그 파일을 `source/`에 두고(`reference/`에는 복사하지 않는다) 어느 시트가 정산표이고 어느 시트가 재무제표인지 사용자 말과 덤프로 확인한다. 불분명하면 묻는다. `SRC`는 그 파일의 재무제표 시트를 가리키면 된다.
2. **읽기**: 두 파일을 `excel-dump.ps1 -Compact`로 덤프해 `verify/`에 둔다(숨은 시트 포함). 원본 엑셀을 반복해 열지 말고 덤프 텍스트만 본다. 도구 소스(`far-run.ps1` 등)는 읽지 않는다.
3. **대응 찾기**: 재무제표의 금액 있는 줄마다, 사용자 정산표에서 **같은 금액(합산이면 합계가 같은 묶음)과 비슷한 이름**을 가진 행을 찾아 그 계정이 어디로 갔는지 확인한다. 이를 마스터 양식(`templates/`)의 어느 행에 넣을지 정한다(양식에 없으면 `ADD`). 한 정산표 행이 여러 계정의 합이면 계정별로 마스터 행에 나누고, 한 계정이 여러 행에 나뉘면 사용자에게 묻는다.
   - **계정 구조의 기준은 사용자 정산표다.** 마스터는 틀(시트·분석 블록·수식)로만 쓰고, 계정 행과 공시계정은 사용자 정산표의 구성을 따른다. 기존 정산표를 받은 **첫 작성**에도 같다.
     - 사용자 정산표에 있는데 마스터에 없는 계정·공시계정은 **비슷한 마스터 행에 합치지 않는다.** `ADD`로 새 행을 만든다(공시계정 칸에는 사용자 정산표의 공시계정명을 쓴다). **새 행의 위치**: `ADD`의 앞계정 칸에는 사용자 정산표에서 그 계정 바로 앞에 있던 계정을 쓴다(그 계정이 마스터에 없으면 그보다 앞의 마스터 계정 중 가장 가까운 것, 같은 합계 그룹 안에서). 마스터에 원래 있던 행의 순서는 바꾸지 않는다(행 이동 도구는 아직 없다). 이 규칙은 1단계의 "성격이 같은 공시계정 행에 넣는다"보다 우선한다.
     - **공시 시트에도 줄이 필요한 경우**(사용자 정산표의 공시계정이 마스터 공시BS·공시IS에 없을 때, K-IFRS 마스터): FAR 계정을 `ADD`로 만들 때 공시계정 칸에 사용자의 공시계정명을 쓰고, 같은 이름의 줄을 `ADDD|공시BS|앞공시계정|새공시계정`으로 공시 시트에 추가한다. 가장 가까운 기존 공시계정에 임시 배정하지 않는다. `ADDD`는 공시BS처럼 합계가 SUM 범위인 시트에 쓰며, 합계를 칸별 수식으로 쓰는 시트(공시IS 등)는 도구가 WARNING으로 알려 주므로 그 경우 사용자에게 보고한다. 순서: `ADD` → `ADDD` → `MAP`.
     - 마스터에 있는데 사용자 정산표에 없는 계정은, 금액이 0이면 `-Prune`이 지우게 두고, 금액이 있으면 사용자 정산표에서 그 금액이 어느 행에 합산됐는지 찾아 그 행으로 `MAP`한다.
     - 이름만 다른 같은 계정(표기 차이)만 같은 행으로 본다. 합칠지 나눌지 애매하면 임의로 정하지 말고 질문 카드로 묻는다.
     - 새로 만든 행과 합친 행은 응답의 보고에 목록으로 낸다(추가 N건, 합침 N건).
4. **저장**: `companies/<약칭>/dict.txt`에 `MAP`/`ADD`/`SKIP`/`TIE`를 쓴다. 금액이 정산표와 일치해 근거가 분명한 항목은 `#[확정] <날짜> 기존 정산표 대조`, 이름 유사성 등으로 정한 항목은 `#[추정] <이유>`로 표시한다. 금액이 0이거나 같은 금액이 여럿이라 정산표만으로 정해지지 않는 항목은 추정하지 말고 모아서 **질문 카드 한 장**으로 묻는다(번호를 붙인다). 답은 `#[확정]`으로 저장한다.
5. **재현 점검**: 같은 결산기로 `job.txt`를 만들어(`far-job-template.txt` 견본 한 장만 본다) `far-run.ps1`을 **`-OutDir companies\<약칭>\FY<연도>\verify`, `-File companies\<약칭>\FY<연도>\verify\setup-check.xlsx`**로 돌린다. 저장 게이트(합계 대조 등)가 통과해야 한다. 그다음 사용자 정산표의 주요 값(자산·부채·자본총계, 매출액, 매출원가, 영업이익, 당기순이익과 정산표에 있는 분석 지표: 회수기일·지급기일 등)을 산출 파일과 비교해 표로 보고한다. **행 단위 일치는 요구하지 않는다**(양식이 다르다). 값이 다르면 사전을 고치고 다시 돌린다. 지표 산식이 회사와 마스터에서 다른 경우는 고치지 말고 "산식 차이"로 보고한다.
6. **보고**: 확정·추정·질문 항목 수, 재현 점검 표(일치/불일치), `setup-check.xlsx` 위치, 다음 기에는 어떻게 시작하는지(「<회사> FY<연도+1> 정산표」만 말하면 됨)를 짧게 보고한다. 비용 때문에 **파일을 처음부터 끝까지 반복해 읽지 않는다**.
- 이 절차로 만든 `setup-check.xlsx`는 정식 산출물이 아니다. 이름을 `FAR_<약칭>_FY...`로 짓지 않고 `outputs/`로 옮기지 않는다.

## 도구는 고치지 않는다 (에이미)

- 에이미가 **고치지 않는 것**: `tools/`의 스크립트, `templates/`의 마스터 양식, `.claude/`의 스킬·에이전트 문서, `tests/`, 앱 코드. 게이트(저장 막는 점검)를 느슨하게 하는 일도 포함한다. 작성자가 자기 작업을 막는 기준을 고치지 않는다.
- 에이미가 **스스로 판단해서 하는 것**: 그때그때 자기 작업 범위 안의 판단 전부 — 계정 대응, 사전·작업 파일·코멘트 파일 작성과 수정, 기존 명령(ADD, ADDD, MAP, SKIP, TIE, ADJ, ACELL, CMT 등)을 어떻게 조합할지, 원인 분석과 해결 방법 선택, 사용자에게 무엇을 물을지. `CELLF`·`NOCHECK`처럼 점검에 영향을 주는 기존 명령은 사용자 승인 카드를 받은 뒤에만 쓴다.
- **도구에 빈 곳이 있어 막히면**: 도구를 고치지 말고 **도구 변경 요청서**를 응답에 적어 사용자에게 보고한다(질문 카드의 선택지에는 "임시로 이렇게 진행"과 "도구 개선 후 재시도"를 넣는다). 요청서에는 ① 증상과 재현 방법(파일 경로, 명령, 오류 줄) ② 영향(어느 회사·몇 건) ③ 어떻게 바뀌면 해결될지 제안 ④ 지금 쓸 수 있는 임시 방법을 적는다. 사용자가 개발 채팅에 전달하면 도구 쪽에서 고치고 테스트한다.

## 빠른 경로 (권장) — 작업 파일 + 계정 사전

같은 회사의 다음 기(期) 작업은 이 경로로 **판단이 필요한 계정만** 처리한다.

1. **계정 사전**(`companies/<약칭>/dict.txt`, 커밋 제외)과 **작업 파일**(`companies/<약칭>/FY<연도>/job.txt`, 사전은 `INCLUDE|..\dict.txt`로 불러온다)을 나눈다.
   - 사전 = `ADD`(양식에 없는 계정 추가), `ADDD`(공시 시트에 줄 추가), `MAP`(원본 계정 → FAR 계정, 부호·그룹 지정), `SKIP`(소계 등 입력하지 않는 원본 줄), `TIE`(원본 합계와 FAR 대조). 한 번 확정하면 회사별로 계속 쓴다.
   - 작업 파일 = `SOURCE`(원본 경로), `SRC`(시트·당기열·전기열), `UNIT`(선택 — 단위 표시가 없는 천원·백만원 원본에만), `COMPANY`, `PERIOD`(개월·기준일), 그리고 `INCLUDE|사전경로`. `ADJ`·`ACELL` 금액은 환산되지 않으므로 원 단위로 적는다.
   - 작성 형식과 예시는 **`tools/far-job-template.txt` 견본 한 장만** 본다(`far-run.ps1`·`far-lib.ps1` 소스를 읽지 않는다 — 읽으면 맥락이 커져 토큰이 낭비된다. 다른 회사의 사전·작업 파일도 견본 삼아 읽지 않는다. 칸 순서가 틀리면 `ERROR` 줄이 알려 준다). 원본 계정 이름은 번호·공백·괄호를 무시하고 비교하며, 같은 이름이 여러 번 나오면 `srcOcc`(몇 번째), FAR 쪽은 `farGroup`(소속 대항목)·`farOcc`로 구분한다.
2. 실행: `powershell -ExecutionPolicy Bypass -File tools\far-run.ps1 -Job <job> -File outputs\<약칭>\FAR_<약칭>_FY<연도>-v<N>.xlsx -Template templates\FAR_master_KGAAP_v1.xlsx -OutDir companies\<약칭>\FY<연도>\verify -Prune`
   - `-Template`을 주면 마스터를 복사해서 처음부터 다시 만들므로 여러 번 돌려도 결과가 같다. `-DryRun`은 저장 없이 점검만.
   - **`-Prune`(기본으로 쓴다)**: 당기·전기 금액이 모두 0인 계정 행을 산출물에서 삭제한다(공시BS·공시IS의 연결 행 포함). 한쪽이라도 금액이 있으면 남는다. 조정분개·질적 판단·코멘트가 있는 행, 분석·검증 수식이 참조하는 행(매출채권, 재고자산 구성, 매입채무, 당기제품제조원가 등), 그룹의 마지막 한 행은 0이어도 남는다. 삭제는 도구가 규칙대로 하며 에이미가 임의로 행을 지우지 않는다. 삭제한 뒤 저장 게이트(FALSE·`#REF!`)가 다시 돌아간다. 다음 기에 잔액이 생긴 계정은 마스터에서 새로 만들기 때문에 자동으로 다시 나타난다.
3. **결과 읽기 (순서대로)**
   - **저장 게이트**: 아래가 모두 만족돼야 저장된다. 하나라도 어긋나면 저장하지 않고 종료 코드 1을 돌려주며, 이유는 `gate.txt`와 실행 출력의 `GATE FAIL` 줄에 나온다. 고치고 다시 돌린다. **`-Force`로 우회하지 않는다.**
     1. `ERROR` 없음(대응 못 찾음 등), 원본 단위가 모순되지 않음(시트끼리 다르거나 `UNIT` 줄과 머리글이 충돌하면 실패)
     2. 금액이 있는 미매핑 원본 줄 0건
     3. `TIE` 줄이 모두 일치(당기·전기)하고 1건 이상 평가됨
     4. `tools/far-required-totals.txt`에 적힌 총계(자산·부채·자본총계, 매출액, 매출원가, 매출총이익, 판관비, 영업이익, 당기순이익, 당기제품제조원가) 중 **원본에 있는 것은 모두 `TIE` 줄이 있음** — 자산총계 하나만 대조해서는 통과하지 못한다. 목록은 회사 양식에 맞게 고쳐도 된다
     5. `far-check`의 FALSE 체크 0건, `#REF!`·`#NAME?`·`#VALUE!`·`#N/A` 0건. `#DIV/0!`은 경고로만 기록되므로 원인(예: 기초잔액 미입력)을 확인해 사용자에게 알린다
     - **게이트가 실패하면 한 번에 고친다.** `false-detail.txt`에 FALSE 칸마다 시트·행 이름·점검 수식·양쪽 값과 차이가 한 번에 나온다. 이 파일과 `tie-out-auto.txt`를 **모두** 읽고 원인을 묶어(예: 같은 계정 때문에 여러 칸이 어긋남) 한 번에 고친 뒤 `far-run`을 돌린다. 원인 하나 고치고 한 번 돌리는 식으로 하지 않는다(한 번에 약 1~1.5분, 에이미 호출 비용이 따로 든다). `TIE`의 열·순번도 `far-run`을 돌려 가며 찾지 말고 `source-dump.txt`로 확인해 한 번에 정한다.
     - **같은 원인으로 3번 연속 실패하면 멈춘다.** 같은 FALSE 칸·같은 TIE 불일치가 3번 연속 남으면 더 시도하지 말고, 지금까지의 원인 분석과 선택지(양식 수식 보정 `CELLF`, 자료가 없는 점검 제외 `NOCHECK`, 회사 자료 확인 등)를 질문 카드 한 장으로 사용자에게 묻는다. **도구·양식·스킬 파일은 어떤 경우에도 고치지 않는다**(아래 "도구는 고치지 않는다" 참고).
     - 공시IS의 **지분법 이익·손실 표시 방식**은 회사마다 다르므로 마스터를 고치지 말고 회사별로 사용자에게 묻고 `CELLF`로 반영한다.
     - 원본 머리글에 단위 표시가 없어 "원 단위로 가정"했거나 `UNIT` 줄만으로 정했으면 `gate.txt`에 `WARN`이 남는다. 이 경우 단위가 맞는지 `source-dump.txt` 금액 규모로 직접 확인하고 제임스 검토 자료의 가정란에 적는다.
   - `unmapped.txt` : 사전에 없는 원본 계정(금액이 있는 것). 새 계정이거나 이름이 바뀐 것이다. 후보 FAR 행이 함께 나온다. 성격 판단 후 사전에 `MAP`/`ADD`/`SKIP`을 추가하고 다시 돌린다. **미매핑이 남은 채로 제임스에게 넘기지 않는다.**
   - `tie-out-auto.txt` : 원본 합계 대조(원 단위로 환산된 값끼리 비교). `DIFF`가 있으면 원인을 찾는다(대응·부호·누락). 사전에 `TIE` 줄을 총계·소계 전부에 둔다(자산·부채·자본총계, 매출, 매출원가, 판관비, 영업이익, 당기순이익, 제조원가 등). `TIE`의 열 칸을 비우면 `SRC`의 당기·전기 열을 쓴다.
   - `div0-list.txt` : `#DIV/0!` 셀마다 행 이름·수식·원인(분모 칸이 0인지 빈칸인지, 입력 칸인지)을 도구가 적어 준다. **에이미는 이 목록으로 모든 `#DIV/0!`을 "분모 0이라 정상" 또는 "입력 필요(기초잔액 등)"로 분류해 응답에 요약**한다(손으로 목록을 다시 만들지 않는다). 설명이 없는 `#DIV/0!`이 하나라도 있으면 제임스가 반려한다.
   - `far-check.txt` : Check 보고(FALSE, 오류, 기간, 중요성, 코멘트, 분석적 절차).
   - `prune-log.txt` : `-Prune`으로 삭제한 행(`DELETED`)과 0이지만 남긴 행(`KEPT`, 이유 포함). 삭제된 계정이 원본에서도 당기·전기 모두 0인지 `source-dump.txt`와 대조해 확인한다.
   - `mapping-log.txt` : 줄마다 원본 행 → FAR 행 대응 기록. 그대로 제임스용 대응표가 된다(수기로 `mapping.txt`를 쓰지 않아도 된다).
   - 분석적 절차 블록의 입력 셀(전기 평균 산정용 기초잔액 등 — 기초매출채권·기초매입채무·기초제품·기초상품·기초원재료)은 작업 파일의 `ACELL|라벨|열|값` 줄로 넣는다(기간별 값이라 사전이 아니라 작업 파일에 둔다). 값이 없으면 해당 지표가 `#DIV/0!`로 남으므로 원본에서 전전기말 잔액을 구할 수 있는지 사용자에게 묻는다.
   - 같은 이름 줄이 많은 원본은 `SRC` 7번째 칸에 `deep`을 주고(가장 오른쪽 글자 셀을 라벨로), `unmapped.txt`가 알려주는 `srcOcc` 번호를 `MAP`에 쓴다. 합계 열에만 값이 있는 줄은 `MAP` 9·10번째 칸으로 열을 지정한다.
   - `MAP` 칸 순서는 `key|원본|FAR|부호|farGroup|srcOcc|farOcc|당기열|전기열`이다. 부호 칸에는 비움, `+`, `-`만 쓸 수 있고(아니면 ERROR), 순번 칸은 숫자만 된다.
   - `-Template`을 쓰면 임시 파일에서 작업하다가 성공했을 때만 `-File`을 교체한다. ERROR로 실패해도 기존 산출물은 그대로다.
   - `[회사명]` 자리표시자는 `COMPANY` 줄이 모든 시트에 채운다. `far-check`에 남았다고 나오는 대괄호 표시는 다른 안내 문구일 수 있으니 내용을 확인한다.
4. 회사 공통 사전의 **판단 사항**(재고자산평가충당금 배정, 성격이 애매한 계정 대응)은 사전 파일의 `#` 주석에 근거를 남기고, 사용자에게 확인을 요청한다. 확인 결과가 나오면 주석을 갱신한다.
5. 코멘트(3단계)와 제임스 검토 자료(4단계)는 기존대로 한다. `source-dump.txt`는 `excel-dump.ps1 -Compact`로 만든다.

이 경로로 되지 않는 경우(양식 구조 변경 등)에만 아래 1단계의 개별 도구를 쓴다.

## 1단계 — 마스터 복사와 계정 대응표 (개별 도구 경로)

1. 마스터를 `outputs/<약칭>/FAR_<약칭>_FY<연도>-v<N>.xlsx`로 복사한다 (PowerShell `Copy-Item`). 마스터 원본은 절대 수정하지 않는다.
2. 재무제표 원본을 `excel-dump.ps1`로 덤프한다. **숨은 시트도 확인**한다.
3. **계정 대응표**를 만든다 — `companies/<약칭>/FY<연도>/verify/mapping.txt`
   - 형식: `FAR행|당기|전기|Dr|Cr` (`far-tool.ps1 -Action Fill`의 입력 형식) + 사람이 읽는 검증용 `원본계정 → FAR 계정 / 원본 위치` 주석 줄(`#`로 시작)
   - 대응표는 원본 한 줄이 FAR의 어느 행으로 갔는지 **빠짐없이** 남긴다. 어디에도 못 넣은 계정이 있으면 임의로 합치지 말고 목록으로 보고한다
   - 양식에 없는 계정은 `far-tool.ps1 -Action AddAccount -AfterRow N -Name …` 로 추가한다 (K-IFRS는 `-Gongsi`로 공시계정 지정). 행 번호가 밀리므로 **추가를 모두 끝낸 뒤 행 번호를 다시 조회해서** 대응표를 쓴다
   - K-IFRS: FAR C열(공시계정)에 이미 정해진 행에 넣는다. 회사 계정명이 달라도 성격이 같은 공시계정 행에 넣고 근거를 대응표에 적는다. (사용자의 기존 정산표가 있으면 "회사 초기 세팅" 절의 계정 구조 규칙이 우선한다.) 성격이 애매하면 추정하지 말고 사용자에게 묻는다
   - 재고자산평가충당금처럼 양식은 유형별인데 회사는 합계 하나인 경우: 임의로 나누지 않는다. 사용자에게 어느 행에 넣을지 묻거나, 재고 유형별 내역 자료가 있으면 그 금액으로 나눈다
4. **부호 규칙**: 재무제표에 보이는 부호 그대로가 아니라 양식의 행 성격을 따른다.
   - 자산·부채·자본은 재무제표 잔액을 양수로 입력하되, 차감 계정(대손충당금·감가상각누계액·평가충당금·자기주식 등)은 **음수**로 입력한다 (마스터의 차감 계정은 별도 행이다)
   - 손익 계정은 재무제표 표시 금액을 양수로 입력하고, 차감·손실 성격은 행 성격(수익/비용)을 따른다
   - 어느 쪽인지 모호하면 `Check` 결과의 합계가 원본 합계와 맞는지로 확인한다

## 2단계 — 입력과 검증

1. `far-tool.ps1 -Action Fill -File <복사본> -Data mapping.txt [-SourceUnit <천원|백만원>] -Company … -CurMonths … -PriorMonths … -CurEnd … -PriorEnd …`
   - `-SourceUnit`은 `mapping.txt`의 당기·전기 금액 단위다(생략하면 원 단위로 가정하고 안내가 출력된다). 이 개별 도구는 원본 머리글을 읽지 못하므로 원본에서 단위를 직접 확인해 넣는다. 당기·전기는 도구가 원 단위로 환산하고, Dr/Cr은 환산하지 않으므로 원 단위로 적는다
   - 회사명은 G5에 넣는다. 사용자가 회사명을 파일 이름·공용 파일에 쓰지 말라고 하면 약칭을 쓴다
2. `far-tool.ps1 -Action Check -File <복사본> -OutFile companies/<약칭>/FY<연도>/verify/far-check.txt`
3. **원본 대조 (필수)**: `far-check.txt`의 자산총계·부채총계·자본총계·매출액·매출총이익·영업이익·당기순이익(있으면 제조원가명세서 당기제품제조원가)을 재무제표 원본 합계와 하나씩 비교해 표로 남긴다. 하나라도 다르면 대응표 오류부터 찾는다.
4. `Check`에서 다음이 모두 만족해야 한다: FALSE 체크 0건(대차, 제조원가), `#REF!`·`#NAME?` 0건, `#DIV/0!`은 분모가 0인 정상적 경우만(왜 뜨는지 확인 가능해야 함), 기간(개월) 입력됨.
5. 분석적 절차 블록(FAR 시트 아래쪽: 비율분석, 매출, 매출원가, 판관비, 매출채권 회수기일, 재고자산, 매입채무)의 수치를 읽고 당기·전기를 비교한다. **산식은 양식에 이미 들어 있다 — 셀에 값을 덮어쓰거나 수식을 고치지 않는다.** 필요하면 사용자에게 산식 변경을 요청한다.

## 3단계 — 분석 코멘트

- 코멘트가 필요한 곳(전기 대비 변동이 유의한 계정, 회수기일·지급기일·재고회전 변동 등)은 워크북에 이미 있는 설명/결론 열(S열 등)에 쓴다.
- **코멘트는 파일에 쓰고 도구가 넣는다.** 엑셀을 손으로 고치거나 회사별 보조 스크립트(PowerShell)를 새로 만들지 않는다. `companies/<약칭>/FY<연도>/comments.txt`(UTF-8)에 줄을 적고, 작업 파일(job.txt) 끝에 `INCLUDE|comments.txt`를 둔 뒤 `far-run`을 다시 돌리면 같은 실행에서 입력되고 저장 게이트도 최종 상태로 돈다(`-Template`로 마스터에서 다시 만들어도 코멘트는 다시 들어간다). 줄은 **계정 이름으로** 찾으므로 행이 밀려도 상관없다.
  - `CMT|FAR계정|FAR그룹|FAR순번|P|R|코멘트` — 본문 계정. P=양적 표시, R=결론 표시(`O`/`X`), 코멘트는 마지막 칸이며 `|`를 써도 된다. **같은 이름이 여러 행이면(예: 급여가 판관비·제조원가에 모두 있음) FAR그룹이나 FAR순번을 반드시 적는다**(안 적으면 ERROR로 알려 준다). 코멘트가 없는 표시 행이 있으면 `far-tool.ps1 -Action Variance`가 알려 준다.
  - `ACMT|번호|확인문구|코멘트` — 분석적 절차 블록의 `<comment>` 자리 중 **번호번째**(위에서부터 1, 2, …; 대소문자 무관). 확인문구는 바로 위 12행 안에 있어야 하는 글자로, 비워도 되지만 적어 두면 행이 밀렸을 때 ERROR로 막아 준다.
  - `ASET|분석행 라벨|순번|열|값` — 분석 블록의 셀 하나를 바꾼다(값이 `=`로 시작하면 수식, `{R:계정명}`은 그 계정 행 번호로 바뀐다). **양식의 산식을 바꾸는 일이므로 사용자 확인이 있을 때만** 쓰고, 근거를 `#` 주석에 적는다(예: 상품 매입 기준으로 산식 변경).
  - `CELL|시트번호|셀|글자` — 다른 시트의 자리표시자 칸(예: 공시BS·공시IS 제목의 날짜)을 채운다. 수식 칸은 거부한다.
  - `CELLF|시트|셀|=수식|사유` — 공시 시트의 수식 칸을 덮어쓰거나 빈 칸에 수식을 넣는다(마스터 수식 결함 보정). **사용자 승인이 있을 때만** 쓰며 사유가 필수이고 gate.txt에 WARN으로 남는다.
  - `NOCHECK|시트|A1:B2|사유` / `NOCHECK|FAR|라벨|순번|오프셋|사유` — 원본에 자료가 없어 점검할 수 없는 FALSE 칸을 저장 게이트에서 제외한다(공시CIE·제조원가명세서 등). **사용자 승인이 있을 때만** 쓰고, 제외 내역은 far-check.txt·gate.txt에 남으며 `미검증`으로 제임스 검토 자료에도 적는다.
  - 견본은 `tools/far-job-template.txt` 맨 아래.
- **근거 없는 원인을 만들지 않는다.** 재무제표 숫자만으로 말할 수 있는 사실("매출채권 회수기일 전기 62일 → 당기 88일, 26일 증가")과 확인이 필요한 질문("증가 원인 확인 필요: 대금 지연, 매출 시점 편중 여부")을 구분해서 쓴다. 기간이 다른 비교(8개월 vs 12개월)는 연환산 전제를 함께 적는다.
- 중요성 금액(L8/K8, 양식의 수식)은 양식이 계산한다. 값을 하드코딩하지 않는다.
- **전기 대비 변동이 큰 계정**(금액이 0이 되거나 새로 생긴 것, 영업이익·판관비·차입금·고정자산·재고·회수기일 등)은 빠짐없이 코멘트를 쓴다. 코멘트 칸을 비워 두거나 `<comment>` 자리표시자를 남기지 않는다.

### 전기 대비 점검 (코멘트 누락 방지)

`far-run`이 `verify/variance.txt`를 만든다. 코멘트를 쓴 뒤에는 최종 엑셀로 다시 점검한다: `powershell -ExecutionPolicy Bypass -File tools\far-tool.ps1 -Action Variance -File outputs\<약칭>\FAR_<약칭>_FY<연도>-v<N>.xlsx -OutFile companies\<약칭>\FY<연도>\verify\variance.txt`
- 표시 기준: `NEW`(전기 0, 당기 있음) · `GONE`(당기 0, 전기 있음) · `SIGN`(부호 반전) · `BIG`(변동액 ≥ 양식의 L8 수행중요성). 기준은 도구가 정하며 에이미가 임의로 바꾸지 않는다.
- 표시된 행은 모두 S열에 코멘트가 있어야 한다. 하나라도 `** NO COMMENT **`이면 종료 코드 1이다 — 코멘트를 쓰고 다시 돌린다. 코멘트가 없는 이유를 "변동 없음"으로 때우지 않는다.
- 합계·소계 행(미처분이익잉여금 같은 계산 행이 걸릴 수 있음)은 해당 계산의 원인 계정 코멘트를 참조하는 한 줄이면 된다.

### 제출 전 자체 점검 (제임스에게 넘기기 전에 모두 확인)

1. 코멘트 열에 `<comment>` 자리표시자가 **0건**이고, `Variance` 점검이 `without comment: 0`인가.
2. `far-check`에 `bracket placeholders remaining`가 나오면 바로 아래 `placeholder cells:` 줄이 알려 주는 **위치와 내용**을 확인해 안내 문구인지 미치환 자리표시자인지 응답에 적었는가.
3. `#DIV/0!`이 남았다면 `div0-list.txt`로 각각 "분모가 0인 정상적 경우"인지, 입력 부족·산식 불일치 때문인지 구분해 응답에 적었는가(0단계 6·7번).
4. 원본 정합성 의문(0단계 8번)과 가정을 응답에 적었는가.

하나라도 못 하면 제임스에게 넘기기 전에 스스로 고친다. 사용자 답이 필요한 것이면 `[확인필요]`로 멈춘다.

## 4단계 — 검토 자료 준비 (제임스용)

제임스는 엑셀을 직접 열 수 없다. `companies/<약칭>/FY<연도>/verify/`에 다음을 둔다.

빠른 경로(`far-run.ps1`): 도구가 만든 `gate.txt`·`mapping-log.txt`(대응표)·`tie-out-auto.txt`·`unmapped.txt`·`far-check.txt`·`prune-log.txt`에 더해, `source-dump.txt`(`excel-dump.ps1 -Compact`로 만든 재무제표 원본 덤프)를 둔다. `div0-list.txt`·`variance.txt`(전기 대비 점검)와 `dict-review.txt`(사전 확정·추정 점검표)도 함께 둔다. 가정(단위·기간·부호·배분)은 `gate.txt`의 `INFO`/`WARN`과 사전 주석으로 갈음하고, 그 밖의 미해결 사항만 에이미가 응답에 적는다.

개별 도구 경로:
- `mapping.txt` — 계정 대응표
- `far-check.txt` — Check 보고
- `source-dump.txt` — 재무제표 원본 덤프 (검토자가 대조할 원본)
- `tie-out.txt` — 원본 합계 vs FAR 합계 대조표와 미해결 사항, 가정(단위·기간·부호·배분)

## 제임스 검토 체크리스트 (FAR)

1. 원본 합계 5~7개(자산·부채·자본총계, 매출, 영업이익, 순이익 등)가 FAR와 일치하는가 — `source-dump.txt`와 `far-check.txt`를 직접 대조
2. 대응표에 원본의 모든 계정이 있고, 잘못된 행(성격이 다른 공시계정) 배정이 없는가. 대응표에 없는 계정 금액이 합계에 남아 있지 않은가 (원본 계정 합 = 그룹 합)
3. 부호·단위: 차감 계정이 음수, 단위 환산 근거가 명시됐는가. 빠른 경로면 `gate.txt`의 `UNIT` 줄(원본 머리글에서 읽은 단위·배수, 또는 원 단위 가정)을 확인하고, `WARN`(원 단위 가정·교차확인 불가)이면 `source-dump.txt`의 금액 규모로 직접 판단한다
4. 검증 셀(대차, 제조원가) 모두 TRUE, `#REF!`/`#NAME?` 없음, `#DIV/0!`은 설명 가능
5. 기간(개월)과 헤더 날짜가 재무제표와 맞는가, 8개월 vs 12개월 같은 비교에서 연환산 해석이 맞는가
6. 분석적 절차 수치를 손으로 다시 계산해 본다 (예: 매출채권 회수기일 = 매출채권 / 매출 × 365 근거 산식은 양식의 수식을 따름). 최소 회수기일·지급기일·비율 2~3개 재계산
7. 코멘트에 근거 없는 원인 단정이 없는가
8. 양식의 수식·서식·시트 구성을 임의로 바꾸지 않았는가, 다른 회사·담당자 이름이 남아 있지 않은가
9. 산출물이 엑셀 한 파일인가 (요청받지 않은 부가 파일 없음)
10. `prune-log.txt`의 `DELETED` 계정이 모두 원본(`source-dump.txt`)에서 당기·전기 0이었는가, 분석에 필요한 계정이 삭제되지 않았는가 (삭제 계정에 금액이 있었다면 반려)
11. `variance.txt`에 표시된 행이 모두 코멘트가 있고(`without comment: 0`), 코멘트가 숫자 사실과 맞는가. `dict-review.txt`의 `추정`·미표시 항목이 이번 결과에 영향을 줬다면 에이미가 그 사실을 응답에 밝혔는가

## 알려진 한계

- K-GAAP 마스터에는 공시CIE(포괄손익)·공시CF(현금흐름표)·주석·분개장이 없다. 요청이 오면 별도 작업으로 확인한다.
- 재고자산평가충당금·대손충당금 등 양식이 유형별인 계정은 1단계의 규칙을 따른다.
- 연결 재무제표(연결조정, 비지배지분 등)는 마스터에 반영돼 있지 않다. 연결이면 시작 전에 사용자와 범위를 정한다.
