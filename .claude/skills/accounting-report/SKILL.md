# 회계 보고서/조서 내용 규칙

이 스킬은 executor(에이미)/reviewer(제임스)의 **역할 정의(작성-검토 분리,
버전 관리, .docx/.pptx 산출 방식 등)와는 분리된, "회계 도메인 콘텐츠
규칙"**이다. 새 업무 유형(예: 클로징 미팅 자료, 고객사 발표 PPT)을
추가할 때는 이 스킬을 그대로 쓰거나, 비슷한 구조의 새 스킬을 만들어
붙이면 된다 — executor.md/reviewer.md 자체를 고칠 필요는 없다.

## 언제 적용하나

- 숫자를 계산·비교·해석하거나, 회계 기준을 인용하거나, 결론/의견을
  담는 문서(실적 보고서, 조서, 검토의견서, 분석 자료 등).
- **적용하지 않는 경우**: 원본 엑셀/리스트를 판단 없이 그대로 다른
  형식으로 옮기기만 하는 작업(예: 자료 요청 리스트를 워드로 변환).
  이런 작업은 "원본 대사 + 구조 보존"만 확인하면 되고, 아래의 합계
  재계산·추정치 라벨링·회계기준 인용 같은 규칙은 해당 사항이 없다.

## 작성 시 반드시 지킬 것 (executor/에이미)

- **숫자는 반드시 `inputs/` 원본에서 가져온다.** 원본에 없는 숫자를
  만들어내지 않는다. 추정치가 필요하면 "추정치"라고 명시하고 근거를
  적는다.
- **합계·소계·증감률은 직접 재계산해서 기재한다.** 원본의 개별 숫자를
  단순히 옮겨적지 말고, 표의 합계/소계/증감률(%)은 작성 시점에 실제로
  계산해서 넣는다. 계산 과정이 복잡하면 산식을 함께 적는다.
- **문서 내 수치 일관성을 스스로 지킨다.** 같은 항목의 수치를 요약·
  본문·표·결론 등 여러 곳에서 언급할 때는 반드시 동일한 값을 쓴다.
  반올림 기준도 문서 전체에서 통일한다.
- **단위와 부호를 문서 전체에서 통일한다.** 원/천원/백만원/억원 중
  하나를 정해 일관되게 쓰고, 적자·감소 등 음수 값은 부호나 괄호로
  명확히 표시한다.
- **기준일·비교 기간을 명확히 하고 통일한다.** 문서 상단에 기준일을
  한 번 명시하고 본문 전체에서 재사용한다. 전기 대비/전년동기 대비
  수치는 비교 대상 기간이 실제로 맞는지 원본에서 확인한다.
- **회계 기준 인용 시 정확히 표기한다.** K-IFRS, 일반기업회계기준,
  회계감사기준 등을 인용할 때는 문서명, 기준 시점, 조항 번호까지
  명시하려 노력하고, 직접 확인하지 못했거나 확실하지 않으면 확인한
  것처럼 쓰지 않고 `미확인`으로 표시한다.
- **결론은 본문 분석 범위 안에서만 쓴다.** 본문에서 다루지 않은
  내용을 결론에서 새로 주장하거나 과장하지 않는다.

## 검토 시 체크리스트 (reviewer/제임스)

- [ ] **숫자 대사**: 산출물의 모든 핵심 수치가 `inputs/` 원본과 일치하는가?
- [ ] **합계·검산**: 표의 합계·소계·증감률(%)을 실제로 재계산했을 때
      표시된 값과 일치하는가? 개별 항목이 맞아도 합산 과정에서 오류가
      날 수 있으므로 반드시 재계산해서 확인한다.
- [ ] **문서 내 수치 일관성**: 같은 항목의 수치가 문서 안 여러 곳에서
      서로 일치하는가? (요약 vs 본문, 본문 vs 표, 표 vs 결론 등)
- [ ] **단위·부호**: 단위 표기가 실제 값 크기와 맞는가? 부호 오류는 없는가?
- [ ] **날짜·기준일 일관성**: 기준일이 문서 전체에서 동일하며, 원본의
      작성 시점·대상 기간과 어긋나지 않는가?
- [ ] **추정치 표시**: 추정으로 작성한 값에 "추정치"라고 명확히
      라벨링되어 있는가?
- [ ] **회계 기준 인용**: 기준서를 인용한 부분이 실제로 맞는 조항인가?
      (확신 없으면 `미확인`으로 표시하고, 문서명·기준 시점·조항이 남아
      있는지도 본다)
- [ ] **결론-본문 정합성**: 결론부의 주장이 본문 분석·수치로 실제로
      뒷받침되는가? 수치는 맞아도 결론이 과장·비약된 경우는 실패로 처리.

## 톤 & 형식

- 답변과 산출물은 한국어를 기본으로 한다.
- 회계 전문 용어는 정확하게 사용하고, 필요하면 관련 기준서(K-IFRS 몇호,
  일반기업회계기준 몇장 등)를 함께 언급한다.
- 보고서/조서 형식은 회계법인에서 흔히 쓰는 구조(요약 → 근거 → 세부
  분석 → 결론)를 기본값으로 하되, `inputs/`에 템플릿이 있으면 그것을
  우선한다.
